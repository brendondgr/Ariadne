Cybersecurity teams increasingly rely on knowledge graphs to represent adversary techniques, attack patterns, and mitigations — but those sources live on different engines with different schemas and query languages, so cross-source correlation today usually means manual lookups or an offline ETL into one graph. Most existing federation approaches assume a single engine or require that translation step up front.

Ariadne instead reads schema and metadata from each **live** source and routes queries natively per engine — Cypher against Neo4j, Gremlin against a Neptune-style server — reconciling results by shared identifiers (ATT&CK technique IDs, CAPEC IDs) rather than a shared index. Every claim in the answer cites a retrieved record and the query that produced it, and the system abstains rather than guesses when a request falls outside the declared schema. Grounding comes entirely from schema descriptions, source metadata, and executed queries; **no vector index or embedding store** is built from the graph data. Named after Ariadne — who guided Theseus through the labyrinth — it threads adversary-technique, attack-pattern, and mitigation graphs into one provenance-linked answer.

## What actually runs

Ariadne is **deterministic by default, with LLM seams that are opt-in and individually backstopped**. This is a design decision the project's own evaluation supports (see [Results](#results)), and it is worth stating plainly because the architecture diagram alone does not show it:

| Stage | Default behavior | LLM seam |
|---|---|---|
| **Planning** | Deterministic drafter: intent classified by a closed regex taxonomy, sources and entities matched against schema labels from the source cards, plan checked by a deterministic self-eval gate ([`utils/planner/`](utils/planner/)) | `PLANNER_LLM_ENABLED` (default `false`) swaps in an OpenAI-compatible drafter, always backstopped by the deterministic one; `--plan-llm` / `--query-llm` enable it per invocation |
| **Query construction** | **Deterministic on every shipped path.** An if-cascade over **31 distinct template labels — 29 of them actual query templates**, of which **19 are exercised by the 120-question bank** — 20 literals declared in the Cypher builder plus two generated by one f-string (`group_software`, `campaign_software`), 14 in the Gremlin builder, and 5 names (`describe`, `describe_by_name`, `expand`, `ambiguous-name`, `unanchored`) declared in both; `ambiguous-name` and `unanchored` are refusal outcomes rather than queries. Each is validated against the source card before execution ([`utils/specialists/cypher/builder.py`](utils/specialists/cypher/builder.py), [`gremlin/builder.py`](utils/specialists/gremlin/builder.py)). Counts derived mechanically by [`docs/plans/robustness/_overnight/derive_templates.py`](docs/plans/robustness/_overnight/derive_templates.py), not read off prose | **Off by default, and it exists only as a baseline.** `SPECIALIST_LLM_QUERY_BUILDER` (default `false`) hands a model the schema and lets it write the Cypher or Gremlin itself ([`utils/specialists/llm_builder.py`](utils/specialists/llm_builder.py)). It was built to be measured against, not to be run: it scores **0.5000** where the template cascade scores **0.9467** on the same unseen questions |
| **Retrieval loop** | `assess → re-plan → specialists`, capped at `ORCH_MAX_HOPS` — **code default 5, but the committed `.env` pins it to `1`, which makes the loop inert on a default local run.** Every arm that measures the loop sets `5` explicitly. Deterministic sufficiency judge over join closure ([`utils/orchestration/`](utils/orchestration/)) | `ORCH_ASSESS_MODE=llm` swaps in a "what's missing" critic with clean fallback; `ORCH_CHASE_FACETS` (default off) extends the frontier to un-fetched facets |
| **Synthesis** | **Claims are composed deterministically on every shipped path** and every one is checked against the retrieved evidence by an unconditional verifier — uncited or ungrounded claims are cut, honest empties become abstentions carrying the executed query as proof ([`utils/synthesis/`](utils/synthesis/)) | `SYNTHESIS_LLM_ENABLED` (default `false`) lets an LLM rewrite the **narrative prose** over the already-verified claims; it cannot add a claim. `SYNTHESIS_LLM_CLAIMS` (default `false`) lets a model *propose* claims — kept as an instrument, never as a default, because it is 67× slower and loses 0.1367 of grounding. It is the only configuration in which the verifier's gates have anything to cut |

Every LLM-off path is byte-reproducible, which is what makes the committed evaluation reports citable.

## Quick Start

One command takes a fresh clone all the way to a running workbench:

```bash
python3 setup.py              # interactive — inspect and confirm each step
python3 setup.py --yes        # non-interactive, accept every default
python3 setup.py --no-launch  # set everything up, then just print the commands
```

The wizard walks five steps, showing what each will run and skipping work already done, so re-running is cheap:

1. **Prerequisites** — checks for `uv`, Node.js, and Docker (CLI + Compose v2 + a running daemon).
2. **`.env`** — creates it from `.env.example`; optionally customize ports and the Neo4j login.
3. **Local inference server** — configures the OpenAI-compatible LLM endpoint (optional) and **probes it**, so you know it's reachable before you query.
4. **Data pipeline** — download MITRE ATT&CK + CAPEC → build canonical graphs → start the Docker stack → load both graphs → verify (the self-healing `--yolo-all` runner).
5. **Web dependencies** — `npm install` for the Next.js workbench.

It then prints the copy-paste commands below and launches the workbench at `http://localhost:16500`.

## Architecture

Four components, each independently testable:

| # | Component | Role |
|---|-----------|------|
| 1 | **Data & schema layer** | Per-source cards (connection details, schema, provenance fields, safety limits) plus reproducible ATT&CK and CAPEC fixtures, sha256-pinned against the raw source snapshot. |
| 2 | **Federated planning agent** | Reads the source cards, classifies analyst intent against a closed taxonomy, and emits a machine-readable plan (target sources, sub-questions, join keys, traversal limits) rather than routing by free-text guess. |
| 3 | **Source-specific query specialists** | A Cypher specialist (Neo4j) and a Gremlin specialist (bounded traversals). Each compiles a read-only template, validates it against the source card, enforces the card's safety limits, and returns normalized, evidence-linked records. |
| 4 | **Synthesis & reporting agent** | Reconciles partial evidence across sources by joining on shared IDs, flags conflicts, and assembles the answer as verified claims-with-citations — every claim checked against the evidence, unsupported claims cut, honest empties turned into abstentions with the executed query as proof. |

**Example flow** — *"Which CAPEC patterns related to credential theft map to ATT&CK techniques, and what mitigations appear for those techniques?"*
The planner emits a CAPEC sub-task and an ATT&CK sub-task → the **Gremlin** specialist finds CAPEC-560/565 mapping to T1555 → the **Cypher** specialist retrieves T1555's mitigations (M1026, M1027) → the synthesis agent joins on the ATT&CK ID and returns a provenance-linked answer.

Full component contracts: [`docs/planner_agent.md`](docs/planner_agent.md), [`docs/specialist_agents.md`](docs/specialist_agents.md), [`docs/agent-interfaces.md`](docs/agent-interfaces.md).

## Key Features

- **Plan-first routing** — the planning agent emits a structured, machine-checkable plan before any specialist runs a query, and a deterministic gate rejects plans that don't validate against the source cards.
- **Bounded, validated queries** — every query is a read-only template gated against the card's declared labels, relationship types, row cap, and traversal depth before execution. A task naming an entity the card doesn't model returns an honest empty with a `boundary` trace instead of silently answering a different question.
- **Verified answers, not generated ones** — claims are composed from the evidence and checked by an unconditional verifier; unsupported claims are cut and kept visible, and abstentions carry the executed query as proof.
- **Reproducible graph artifacts** — a canonical (JSONL + schema + manifest) → export (Neo4j CSV/Cypher, Gremlin JSONL) → runtime layering, sha256-pinned to the raw source, with a fixture-QA harness that reconciles raw == manifest == live before agents ever query it.
- **Self-healing pipeline runner** (`--yolo-all`) — classifies failures as stale-state (auto-backup + rebuild), transient (retry with backoff), or needs-human (surfaced, not crashed on), instead of failing the whole run on the first error.
- **Memory-inclusive chat threads** — the workbench is a threaded chat: persisted conversations in a date-grouped sidebar (stdlib-SQLite, LLM auto-titled), cross-turn memory so a follow-up ("tell me more about T1598") resolves from prior turns, and a router that answers from memory when it can or re-queries the graphs when it must — with the grounded Answer Card kept as the trust surface beneath every reply.
- **Analyst web workbench** — a Next.js app with three surfaces: a **chat view** streaming the live plan → query → evidence → answer pipeline, an **interactive graph explorer** (switch between the ATT&CK/Neo4j and CAPEC/Gremlin graphs, render every node and edge on canvas, search, filter by node/relationship type, inspect any element's properties), and an **evaluation view** that renders the committed component + end-to-end reports and can re-run the end-to-end evaluation live.
- **A launcher that proves the stack** — `uv run app.py` preflights everything the pipeline needs (toolchain, ports, source cards, both graph backends, the LLM endpoint, and a compile of the LangGraph super-graph), gates on real readiness probes, prints a status board with per-subsystem verdicts and named remediations, and streams a startup smoke query over the same SSE contract the UI uses.

### The July arm study, kept as history

The seven-arm study below is [`docs/evaluation/2026-07-26/`](docs/evaluation/2026-07-26/README.md): seven full runs over the 120-question golden catalogue against the live graphs, each answer graded by an **independent Sonnet 5 agent** (one per question, 840 agents in total) against the question's gold assertions *and* its full retrieved evidence. Cross-model on purpose — the pipeline's own model does not grade its own output.

⚠️ **These figures are development-set figures on a model that no longer exists behind the endpoint that produced them** (see [Model provenance](docs/evaluation/README.md#the-model-behind-skynet)). They are kept because they are the record of what was measured, not because they describe the system today.

| Configuration | Plan | Synthesize | correctness | verdicts | hallucinations | wall clock |
|---|---|---|---|---|---|---|
| **A — deterministic** | authored | deterministic | **0.9972** | **120/0/0** | **0** | **1.6 s** |
| **F — determ. + loop + LLM writer** | authored | LLM over verified claims | 0.9957 | 119/1/0 | 3 | 533 s |
| E — LLM-planned + loop | **LLM** | LLM over verified claims | 0.8560 | 97/7/16 | 15 | 1,043 s |
| B — LLM-planned | **LLM** | LLM over verified claims | 0.8505 | 92/14/14 | 12 | 1,020 s |

*(verdicts = CORRECT / PARTIAL / INCORRECT)*

Three findings drove the current defaults:

1. **LLM planning is where the loss concentrates.** Holding extraction and synthesis constant, the LLM-planned arm loses **0.119 correctness** against its deterministic-planned counterpart (B 0.8505 vs C 0.9690), and **0.140** against the best deterministic-planned arm (E 0.8560 vs F 0.9957). A mechanical failure-localisation pass showed only 2 of Arm B's 36 failures were faithfulness — 26 of 36 were planning or retrieval, the opposite of the intuition that LLM answers fail by making things up. ⚠️ **Two caveats, both added 26 August.** The localisation *mechanism* is published prior art (Leung et al., EACL 2026), and their distribution runs the other way — generation is 32.7% and 76.4% of their errors. Why ours inverts is an open question (`Q24`) and is not yet written down.
2. **Retrieval volume is not the lever.** Arm B retrieves 2.6× more evidence than Arm F and surfaces 20% *less* of the gold.
3. **The accuracy-versus-readability trade is not real** — once the narrator is bound to the *verified claims* rather than left to re-read raw evidence, readable prose costs 0.0015 correctness with zero INCORRECT verdicts.

Component and end-to-end reports, deterministic and reproducible: query validity at the ceiling **by construction** (the specialists fill templates rather than free-generating), cross-source join exact-set-match 30/30, CAPEC→ATT&CK mapping recall 113/113, provenance completeness 120/120. See [`docs/evaluation/`](docs/evaluation/README.md).

⚠️ **Three of those numbers were withdrawn or superseded and the honest versions are:**

- **Planner source recall and schema adherence are not reported as measurements.** They were 1.0 *by construction* — `utils/planner/evaluation/build_corpus.py` builds the corpus by running the planner under test and discarding every case it gets wrong. Recorded as `Q7`, resolved by relabelling rather than re-scoring. `intent_accuracy_rate` and `mean_entity_recall` survive as genuine measurements.
- **The safety block rate is now 240/240, and getting there found 15 live bypasses** the original 17 hand-written probes never reached — including eight TinkerPop `mergeV`/`mergeE` placements that *mutate* and that no source card named ([`EXP-2026-08-016`](docs/research/experiments/EXP-2026-08-016-tenant-isolation/)). Quote 240/240 with the 15 attached; the small suite passing was weak evidence of a strong property.
- **Three of the four end-to-end `goals.md` metrics are self-consistency checks**, not correctness metrics, and the repository's own analysis says so (`Q8`, resolved by relabelling).

### What these numbers do and don't show

Recorded here so they are not over-read, and expanded in the standing record's limitations section:

- **All 120 questions are anchored** — every one names an entity or an id. Open-ended questions are still unmeasured; paraphrased ones are measured and the result is bad (see the variant row above).
- **The catalogue was authored alongside the system** and is used for development, not held out. Each question carries an `expected_template` field. The price of that is now measured: **0.0483**.
- **Both baselines now exist** — an LLM writing its own Cypher and Gremlin, and a merged single store — and the merged one came back a null. Neither is a *published external system*; no comparator from the literature has been run.
- **The judge is a model.** Cross-model and evidence-grounded for the July arms; the August judged comparisons used a **local grader calibrated at r = 0.9275** against those Sonnet judgments, which the record itself calls fine for comparing arms and not a publication figure. On a foreign schema the same local grader overstated faithfulness by **0.43**.
- **Not one model, and not one day.** The `skynet` endpoint is a relay *alias* and it has served three different models over the life of this project. Every figure is dated evidence about whatever was behind the alias that day — see [Model provenance](docs/evaluation/README.md#the-model-behind-skynet).

The portability question — what survives a dataset that isn't MITRE — was *audited* in [`docs/evaluation/2026-07-26/portability.md`](docs/evaluation/2026-07-26/portability.md) and has since been *measured*. ⚠️ **The audit was optimistic and the measurement says so.** Pointed at a real 72-label customer identity schema with no changes, both arms retrieved **nothing at all** — and the failure was in the planner, which the audit had classified as portable, not in the templates it had counted. Entity extraction is card-driven but not schema-*scale*-independent: it degrades from usable at 11 labels of distinctive jargon to unusable at 72 labels of ordinary IT English, with no code change and no error. After five structural fixes the schema-derived path reaches **0.7877** on 117 blind questions while the template cascade reaches **0.3177**. Full record: [`EXP-2026-08-011`](docs/research/experiments/EXP-2026-08-011-identity-schema-transfer/).

## Challenges & Design Decisions

**One plan schema, two query languages.** Cypher and Gremlin don't share a traversal model, so the planner can't emit engine-specific queries itself without becoming two planners. It instead emits an engine-agnostic plan (sub-questions, entities, join keys, traversal limits) and pushes engine-specific query construction down into each specialist — keeping the planner swappable and the specialists independently testable. Adding a third query language is documented as four targeted changes in [`docs/migration-guide.md`](docs/migration-guide.md).

**Templates over free generation.** The specialists compile hand-written, card-validated templates instead of letting a model write Cypher or Gremlin. Query validity and safety adherence hold by construction, and a model given the same schema scores 0.5000 against the cascade's 0.9467.

⚠️ **But what the templates buy is not what this section used to claim.** A schema-derived generic path, with every hand-written template disabled, judges *level* with the cascade on ATT&CK and CAPEC and beats it by roughly 0.61 on a schema nobody wrote templates for. The templates hold **precision and provable abstention on the schema they were written for** — which of several schema-valid readings the analyst meant — and that advantage reverses off it. The claim that the templates hold the accuracy (`C-003`) is **refuted** in the project's own ledger and superseded by `C-023`.

**Reproducibility against a live, external data source.** MITRE ATT&CK and CAPEC change over time, but behavior needs to be reproducible for evaluation. The build pipeline pins a sha256 snapshot of the raw source at download time and gates every rebuild on that pin, with a fixture-QA harness that checks raw == manifest == live before anything is loaded — catching schema drift before it reaches an agent instead of after.

## Status

The data layer, the federated planning agent, both query specialists, the verifying synthesis agent, and the end-to-end pipeline integration are complete: one LangGraph `StateGraph` orchestrator ([`utils/orchestration/`](utils/orchestration/), shared by the CLI and the API through `run_pipeline`/`iter_pipeline`) runs plan → dependency-sequenced specialists → assess → verified synthesis with per-stage latency. An analyst web workbench sits on top — chat, graph explorer, and evaluation dashboard.

Component-level evaluation (`--component-eval`) and end-to-end evaluation (`--e2e-eval`) are complete and committed, as is the controlled seven-arm study that produced the July table above. The Wk 14–15 technical documentation set is delivered: source card format ([`docs/source_cards.md`](docs/source_cards.md)), agent interface contracts ([`docs/agent-interfaces.md`](docs/agent-interfaces.md)), the query safety model ([`docs/query-safety.md`](docs/query-safety.md)), and the openCypher/GQL migration guide ([`docs/migration-guide.md`](docs/migration-guide.md), proposal Deliverable #6).

Since then the project has run **20 further experiments** — blind holdouts, both baselines, external validation against two published benchmarks, a third live source with a declared cross-graph bridge, a 240-probe safety audit, and a 699-run paraphrase-robustness study. The record is [`docs/research/INDEX.md`](docs/research/INDEX.md); the current outside assessment is [`docs/research/audit-2026-08-31.md`](docs/research/audit-2026-08-31.md).

**Known open work**, in priority order, is [`docs/research/OPEN_QUESTIONS.md`](docs/research/OPEN_QUESTIONS.md). The four that block publication today: explaining why this project's failure distribution runs opposite to the only comparable published one (Q24), re-grading the headline comparisons with a cross-model panel, deciding whether the question banks emit executable gold queries (Q26), and the contamination control that has never been run.
