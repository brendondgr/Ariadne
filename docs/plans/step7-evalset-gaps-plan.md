# Step 7 — Plug the Holes in the Test Set (Campaign Coverage, Negative Asset Questions, Generated Gold)

## 1. Introduction

Step 5 built the golden evalset (45 AI-verified single-source questions gating both specialists) and Step 6 made the final answer prove itself (claim verification + enforced abstention). Step 7 plugs two measured gaps in that test set. First, **Campaign coverage**: Enterprise ATT&CK v19 has 56 live Campaign objects (confirmed against both the pinned STIX bundle and the loaded Neo4j graph: 52 campaigns carry `USES` edges to top-level Techniques, 25 carry `ATTRIBUTED_TO` edges to Groups), yet the bank holds only two Campaign *lookup* questions — no relationship questions at all, and the Cypher builder has no campaign templates, so the system's ability to answer "which techniques did campaign C0027 use" or "which group is C0028 attributed to" is currently unmeasured and, in fact, unroutable. Second, **negative Asset questions**: Assets exist only in ICS ATT&CK, not the Enterprise data loaded here, so the correct answer to "what assets does T1047 target" is a graceful "that's not in this source." Today the specialist would silently degrade such a task to a node lookup and answer a *different* question — precisely the wrong-but-plausible failure mode Steps 5–6 exist to catch. These trick questions therefore do double duty: they add coverage and they exercise the Step 6 abstention behavior at a boundary the retrieval layer cannot see.

The third Step 7 point is a discipline, not a gap, and it is already structurally in place: every gold answer is materialized from the pinned snapshot by `utils/specialists/evalset/gold_bank.py` (never hand-keyed), and `test_regeneration_is_deterministic_and_matches_committed` fails the suite if the committed bank drifts from what the pinned data produces. This plan extends that same machinery — new campaign gold maps are *parsed from the raw STIX bundle*, question assertions are *resolved from the bank at compile time*, and the new claims get the same two-independent-AI-verifier audit used in Step 5 — so the discipline holds for everything added here.

## 2. Gaps & Unanswered Questions

- **Which campaign relationships to cover?** The loaded graph carries `Campaign-USES->Technique/SubTechnique/Software` and `Campaign-ATTRIBUTED_TO->Group`. *Assumption*: cover the two analyst-meaningful ones — techniques used and group attribution — mirroring the existing `group_techniques` template style (top-level `Technique` matches; gold filtered by label the same way `_top_level_techniques` already does).
- **How should the Asset refusal be produced — planner gate or specialist?** In the full pipeline the plan gate already rejects sub-questions with entities not in any card (they become `unsupported` notes). But the golden suites run specialists directly, and a gate rejection is a planner artifact, not an analyst-graceful answer. *Assumption*: add a **schema-boundary refusal** in the shared `QuerySpecialist` — when `resolved.unknown_entities` is non-empty the specialist returns an honest empty (`ok=True`, zero records, **no query executed**, a `boundary` trace naming the unknown entities) instead of silently answering a different question. Synthesis then abstains. No existing bank task carries unknown entities (verified before implementation), and planner-routed tasks never reach this guard because the gate fires first, so the change is behavior-adding, not behavior-changing.
- **What is the abstention "proof" when no query ran?** Step 6's abstention proof is the executed query; a boundary refusal has none by design. *Assumption*: extend the abstention statement with a boundary variant ("the source doesn't model these entities — no query can express this question") while keeping `Abstention.query` empty; the proof is the specialist's boundary trace naming the unknown entities, which the statement carries. The golden synthesis checker gets a distinct assertion path for these (`expect_boundary`) so the executed-query-proof invariant stays strict for genuine empties.
- **Anchor choice for campaign questions.** *Assumption*: anchors with verified-rich gold — C0027 (Triton Safety Instrumented System Attack, 10 top-level technique uses, attributed to G1015), C0028 (attributed to G0034), plus a third technique-usage anchor picked from the bank at implementation time; one nonexistent-campaign negative (C9999). Exact top-5 membership is resolved from the gold bank at compile time, never typed by hand.
- **CAPEC side.** Step 7 names no CAPEC gap. *Assumption*: no CAPEC bank changes; the boundary-refusal guard lives in the shared base so it applies to both specialists automatically.
