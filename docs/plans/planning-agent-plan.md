# Federated Planning Agent — Implementation Plan

### 1. Introduction

This plan builds the **federated planning agent** (roadmap Wk 6–7, `goals.md`). The planner does exactly one job: it **reads the source cards, learns which graphs are live right now, classifies an analyst request, and emits a machine-readable plan** (target sources, sub-questions, join keys, per-sub-question traversal limits, and explicitly unsupported parts). It *routes*; it never queries. Everything downstream of the plan — specialist query generation, connector enforcement, synthesis, orchestration — is out of scope here.

The governing principle from the briefing is **"the LLM drafts, deterministic code grades."** The planner is a self-evaluating ReAct loop: a pluggable *drafter* proposes a plan, and a **fully deterministic self-evaluation gate** validates that draft against ground truth (the live-source view + the source cards) before it ships. If the draft names a dead source, a nonexistent label, an undeclared join key, or omits required limits, the gate bounces it back with a specific reason; the loop revises up to a small cap and otherwise degrades to an honest partial plan. The drafter is hybrid per the project decision: a deterministic rule-based drafter is the default (so the whole agent is testable with no model in the loop), and a configurable **OpenAI-compatible LLM drafter** (default endpoint `http://localhost:9090/v1`, model `default-model`) is selected when configured.

Discovery is grounded in the real environment: the live CAPEC graph is already loaded in Gremlin (4,888 vertices on `ws://localhost:6455/gremlin`), while Neo4j is up but unauthenticated in this worktree — a perfect live exercise of the "source down / unsupported" degrade path. Source cards are generated by `--build` (already run); because the authored overlays were removed and git-ignored, `connection`/`safety`/`provenance`/`entity_descriptions` are empty on the generated cards, so the planner carries a **committed card-enrichment layer** that supplies safety limits, canonical join keys, and routing glosses without reintroducing overlays.

All work lands in a new `utils/planner/` package with its own test corpus, mirroring the existing `utils/graph_loader/` and `utils/kg_builder/` structure. Each phase is validated and then committed (no push, per the session instruction); the branch is merged to `main` only when everything is 100% functional.

### 2. Gaps & Unanswered Questions

- **Drafter strategy** — *Resolved by user:* hybrid. A `PlanDrafter` protocol with a deterministic default drafter and a configurable OpenAI-compatible LLM drafter pointed at `localhost:9090` / `default-model`. *Assumption:* the LLM endpoint speaks the standard `/v1/chat/completions` contract; it is reached with the project's `requests` dependency (no heavy SDK) and is **opt-in** — absence or unreachability degrades to the deterministic drafter, never crashes.
- **Source cards** — *Resolved by user:* run full `--download` + `--build all` (done). Generated cards lack authored sections. *Assumption:* the planner enriches generated cards from a committed `card_enrichment` module rather than reintroducing git-ignored overlays; conservative safety defaults follow `docs/source_cards.md` (`max_result_rows=1000`, `max_traversal_depth=3`, `query_timeout_ms=5000`, `read_only=true`).
- **Canonical join key** — The cross-source bridge is the ATT&CK `technique-id` ↔ CAPEC `MAPS_TO` → `TaxonomyEntry` declaration (from `purpose.md` / the framework build plan). *Assumption:* this single declared bridge is the only canonical join key; the planner never invents another and marks any other cross-source need unsupported.
- **Neo4j auth in this worktree** — The running `ariadne-neo4j` container rejects the default password and no `.env` exists here. *Assumption:* we do **not** restart or re-credential the user's running container. Discovery treats Neo4j as not-live (unauthorized → down); the ATT&CK card still loads and is fully unit-tested with a fake/in-memory probe. This is a feature demo of §2.1/§2.2, not a blocker.
- **Push policy** — Global rules say "always push," but the session instruction says **commit only, do not push**. *Resolution:* the session instruction wins. Each step commits to git locally with the stated message; nothing is pushed. The branch is merged into `main` locally at the end.
- **Workflow/agent tiering** — Per instruction, repository searches use Haiku subagents, code implementation uses Sonnet subagents, and planning/integration stays with Opus. Phases with independent files fan out; dependent phases are integrated directly.

### 3. Hierarchical Step-by-Step Instructions

#### Step 1: Planner package scaffold + source-card loader & enrichment (briefing §1)

- **Locations**:
  - `utils/planner/__init__.py` — package exports.
  - `utils/planner/cards.py` — `SourceCardView` dataclass (introspected fields: `node_labels`, `relationship_types`, `node_properties`, `allowed_edge_patterns`, plus enriched `safety`/`provenance`/`entity_descriptions`/`connection`); `load_source_cards(data_dir)` reading `data/source_cards/*.json`; `assert_card_consistency()` enforcing that routing reasons only over introspected fields (§1.1).
  - `utils/planner/card_enrichment.py` — committed `ENRICHMENT` table (per-dataset `safety` defaults, `provenance` `id_property`/`id_scheme`/`source_name`/`dataset_version`, `entity_descriptions` glosses) and `enrich(card)` that layers authored metadata onto generated cards without overlays.
  - `utils/planner/join_keys.py` — `CANONICAL_JOIN_KEYS` declaring the `technique-id` ↔ CAPEC `MAPS_TO`→`TaxonomyEntry` bridge and `resolve_join_key(card_a, card_b)` returning a binding only when the key is present in both cards (§1.2).
  - `utils/planner/config.py` — `PlannerConfig` reading planner env knobs (LLM base URL/model/toggle, probe timeout, cache TTL, max iterations) through `utils.config.env_str/env_int/env_bool`.
  - `utils/planner/tests/test_cards.py`, `tests/test_card_enrichment.py`, `tests/test_join_keys.py`, and committed fixtures under `utils/planner/tests/fixtures/source_cards/` (small authored `attack.json` + `capec.json`).
- **Rationale**: The planner's only ground truth is the cards; everything downstream reasons over `SourceCardView`. Building the typed view, the enrichment layer, and the declared join-key registry first means later phases (gate, drafter) consume a stable, fully-populated input. Fixtures decouple tests from the heavy generated cards.
- **Action**: Undergo the verification/tests/validation process for this phase (`uv run python -m pytest utils/planner/tests/test_cards.py utils/planner/tests/test_card_enrichment.py utils/planner/tests/test_join_keys.py`; load the real generated cards and confirm enrichment fills safety/provenance/join keys). Once validated, commit to GitHub (no push) stating: Planning Agent (1/7) Complete: Added planner package scaffold, typed source-card view, committed card-enrichment layer, and declared canonical join-key registry with fixtures and unit tests.

#### Step 2: Discovery / liveness content probe — "read the active graphs" (briefing §2)

- **Locations**:
  - `utils/planner/discovery.py` — `LiveSource` dataclass (dataset, backend, reachable, node_count, observed_labels, reason); `probe_source(card, config)` running a **content probe** (connect → `count_nodes()` non-trivial → confirm a couple of expected `count_by_label()` exist), not a bare socket open (§2.2); each probe runs in a worker thread with its **own short timeout** so a half-dead backend cannot stall planning (§2.3); `LiveSourceView` with a short TTL cache and `get_live_sources(cards, config, force=False)` that **re-probes per request** (§2.1, §2.4). Reuses `Neo4jGraphStore`/`GremlinGraphStore` from `utils/graph_loader/stores/` (constructed with empty `export_files`, calling only `connect`/`healthcheck`/`count_*`). Unreachable, unauthorized, or empty ⇒ `reachable=False` with a reason.
  - `utils/planner/tests/test_discovery.py` — unit tests with fake stores: live-with-content ⇒ live; reachable-but-empty ⇒ down (§2.2); raises/hangs ⇒ down via timeout (§2.3); cache reused within TTL and re-probed after expiry (§2.4).
- **Rationale**: This is the planner's "know what graphs are running *right now*" requirement and the literal "read the active graphs in the Docker container" deliverable. It must reflect reality at planning time, not registry intent, and must never block on a stalled backend. The gate (Step 3) consumes this view as ground truth.
- **Action**: Undergo the verification/tests/validation process for this phase (`uv run python -m pytest utils/planner/tests/test_discovery.py`; run a live probe script against the real Gremlin/Neo4j and confirm CAPEC reports live with 4,888 vertices and Neo4j reports down-with-reason). Once validated, commit to GitHub (no push) stating: Planning Agent (2/7) Complete: Added per-request content-probe discovery with own-timeout liveness, short-TTL caching, and a live read of the active Gremlin CAPEC graph plus the Neo4j degrade path.

#### Step 3: Plan schema + deterministic self-evaluation gate (briefing §3.5, §4, §5.3)

- **Locations**:
  - `utils/planner/schema.py` — `SubQuestion` (source, text, entities, `join_key` optional, **required** `limits` with `max_traversal_depth`/`max_result_rows`/`query_timeout_ms`), `JoinDeclaration`, `UnsupportedPart` (what + why), `Plan` (sub_questions, joins, unsupported, source-selection rationale, assumptions, `partial` flag); `Plan.to_dict()`/`from_dict()` for the machine-readable emit.
  - `utils/planner/gate.py` — `evaluate(plan, cards, live_view)` returning `GateResult(ok, reasons)`; **fully deterministic** set-membership checks (§4.2): every named source in the live-source view; every sub-question entity in that source's card `node_labels`/`relationship_types`; declared join keys real & canonical via `join_keys.resolve_join_key` (§1.2); per-sub-question limits present and within the card's `safety` bounds (§3.5, §4.1); structural-only, not stylistic, so ambiguous-but-valid plans pass (§4.3); **non-degeneracy** — the plan must address at least the answerable portion or be explicitly marked partial (§5.3).
  - `utils/planner/tests/test_schema.py`, `tests/test_gate.py` — accept a good plan; reject dead source, nonexistent label, undeclared/invalid join key, missing limits, out-of-bounds limits, and degenerate/empty plan; confirm a valid-but-loosely-phrased plan still passes (not too strict).
- **Rationale**: This is the core safety mechanism — "the LLM proposes, this gate disposes." It must be deterministic code (not a model self-grade) so the loop is honest, strict enough to catch unroutable plans, and bounded enough that valid plans pass. Defining the schema here pins the contract every drafter must satisfy.
- **Action**: Undergo the verification/tests/validation process for this phase (`uv run python -m pytest utils/planner/tests/test_schema.py utils/planner/tests/test_gate.py`). Once validated, commit to GitHub (no push) stating: Planning Agent (3/7) Complete: Added the machine-readable plan schema and the fully-deterministic self-evaluation gate (live-source, entity, join-key, limits, and non-degeneracy checks).

#### Step 4: Plan drafters — deterministic default + OpenAI-compatible LLM (briefing §3)

- **Locations**:
  - `utils/planner/drafter.py` — `PlanDrafter` protocol (`draft(request, cards, live_view, feedback) -> Plan`); `DeterministicDrafter` doing card-grounded keyword routing over `entity_descriptions`/labels, recording source-selection rationale (§3.1), avoiding redundant sub-questions and covering each distinct part (§3.2), marking unsupported parts and never fabricating (§3.3), and stating assumptions for ambiguity (§3.4); it consumes gate `feedback` to revise.
  - `utils/planner/llm_drafter.py` — `OpenAICompatibleDrafter(config)` posting to `{base_url}/chat/completions` with `requests`, a strict JSON-plan system prompt embedding the live cards + live-source view, parsing the response into `Plan`; on any transport/parse error it raises a typed `DrafterUnavailable` so the loop falls back to the deterministic drafter.
  - `utils/planner/drafter_factory.py` — `select_drafter(config)` returning the LLM drafter when enabled+reachable, else the deterministic one (hybrid).
  - `utils/planner/tests/test_deterministic_drafter.py`, `tests/test_llm_drafter.py` — deterministic routing/decomposition/unsupported/assumption tests; LLM drafter tested with a mocked `requests` response for parsing, plus a guarded live test that runs only if `localhost:9090` answers.
- **Rationale**: The drafter is the one probabilistic seam; isolating it behind a protocol keeps the gate and loop fully testable without a model, satisfies the hybrid decision, and lets the LLM enter as late as possible. The deterministic drafter doubles as the always-available fallback.
- **Action**: Undergo the verification/tests/validation process for this phase (`uv run python -m pytest utils/planner/tests/test_deterministic_drafter.py utils/planner/tests/test_llm_drafter.py`; probe `localhost:9090` and, if up, run one real draft). Once validated, commit to GitHub (no push) stating: Planning Agent (4/7) Complete: Added the PlanDrafter protocol with a card-grounded deterministic drafter and a configurable OpenAI-compatible LLM drafter (localhost:9090/default-model) with graceful fallback.

#### Step 5: Self-evaluating ReAct loop controller (briefing §5)

- **Locations**:
  - `utils/planner/agent.py` — `PlanningAgent.plan(request) -> Plan`: get the fresh live-source view (Step 2) → draft (Step 4) → gate (Step 3) → on failure, feed the gate's **specific** rejection reason into the next draft (§5.2) and revise, up to a `max_iterations` cap of 2–3 (§5.1); on exhaustion, emit the best partial plan with the unresolved parts named, never an infinite loop and never a fabricated plan to escape the gate (§5.1); guarantee the emitted plan is non-degenerate or explicitly `partial` (§5.3); attach a full plan trace (each Thought/draft/gate-verdict) for inspectability.
  - `utils/planner/tests/test_agent_loop.py` — converges within cap; caps out ⇒ partial plan with reasons; gate feedback visibly changes the next draft; loop never emits a degenerate plan as success; unsupported-only request ⇒ honest empty-but-marked plan.
- **Rationale**: The loop must terminate cleanly whether or not it converges, with informed (not blind) revises. This ties discovery, drafter, and gate into the single `plan()` entry point downstream phases (out of scope) would call.
- **Action**: Undergo the verification/tests/validation process for this phase (`uv run python -m pytest utils/planner/tests/test_agent_loop.py`). Once validated, commit to GitHub (no push) stating: Planning Agent (5/7) Complete: Added the bounded self-evaluating ReAct loop with feedback-driven revision, max-iteration cap, honest partial-plan degradation, and a full inspectable trace.

#### Step 6: Evaluation harness + expected-plan corpus (briefing §6)

- **Locations**:
  - `utils/planner/evaluation/corpus.py` + `utils/planner/evaluation/expected_plans/*.json` — a small, manually-reviewed set of (request → expected plan) pairs including out-of-scope and partially-answerable requests so the "mark unsupported" behavior is tested (§6.2); a held-out split frozen as regression checks (§6.3).
  - `utils/planner/evaluation/scorer.py` — `score_plan(actual, expected)` measuring **plan-level** metrics only (§6.1): source-selection accuracy, sub-question quality, unnecessary-source-call count, and schema adherence — decoupled from downstream answer success.
  - `utils/planner/evaluation/run_eval.py` — runs the agent (deterministic drafter for determinism) over the corpus and prints a metrics report.
  - `utils/planner/tests/test_evaluation.py` — scorer unit tests + a corpus regression test asserting the deterministic agent meets a passing bar on the held-out cases.
- **Rationale**: The planner is scored on its *plan output*, not end-to-end answers, so a good plan is never blamed for a downstream failure. A fixed expected-plan set with out-of-scope cases is what makes the score objective and guards against overfitting/regressions.
- **Action**: Undergo the verification/tests/validation process for this phase (`uv run python -m pytest utils/planner/tests/test_evaluation.py`; `uv run python -m utils.planner.evaluation.run_eval` and confirm the metrics report). Once validated, commit to GitHub (no push) stating: Planning Agent (6/7) Complete: Added the plan-level evaluation harness, expected-plan corpus (incl. out-of-scope/partial cases), scorer, and frozen regression checks.
