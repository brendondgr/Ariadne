# LangGraph Orchestration Migration Plan

> **Plan name for commits:** `LangGraph Migration`
> **Commit policy:** Per the standing user directive, every step ends with a local `git commit` + a `docs/changelog.jsonl` entry — **never push**.

---

## 1. Introduction

Ariadne's Q/A pipeline is currently orchestrated by a hand-rolled synchronous generator, `iter_pipeline` in `utils/specialists/pipeline.py`, which composes `probe → plan → [sequenced specialists] → bundle → synthesize → done` and yields `(event, payload)` tuples that the CLI (`utils/specialists/cli.py`) and the API SSE layer (`api/services/query.py`) present. The planner's self-evaluating draft→gate→revise loop lives in `utils/planner/agent.py`, and synthesis composition (deterministic claims + LLM narrator + mandatory verifier) lives in `utils/synthesis/factory.py`. This plan converts that custom orchestration into a **LangGraph agent-driven workflow**: a top-level `StateGraph` with a shared typed state, the planner and synthesis stages as composable subgraphs, specialists as graph nodes with conditional dependency routing, and LangGraph's streaming (`stream_mode="custom"` via `get_stream_writer()`) reproducing the exact event vocabulary the web UI already consumes.

The approach is **strangler-fig, seam-preserving**: the domain logic (drafters, gate, `QuerySpecialist`, federation bundling, composer/narrator/verifier) is *not* rewritten — it is re-hosted as LangGraph nodes. The public seams (`PlanningAgent.plan()`, `iter_pipeline`/`run_pipeline`, `synthesize()`) survive as thin adapters over compiled graphs so the ~1,000-test regression suite, the SSE contract, the web frontend, and the evaluation harness (`utils/evaluation/score_e2e.py`) keep working at every step. Package layout follows the repo's own reference at `docs/skills/repository-structure/structures/langgraph.md` (graph wiring / nodes / state separated per agent under one orchestration package).

## 2. Gaps & Unanswered Questions

- **LangGraph version & footprint**: The repo has no LangChain-ecosystem dependency today. *Assumption*: add `langgraph>=1.0` and `langchain-core` only — **not** `langchain-openai` or the wider `langchain` package. The three LLM call sites (planner `OpenAICompatibleDrafter`, synthesis `narrator`/`OpenAICompatibleComposer`, eval `OpenAICompatibleJudge`) keep their existing raw OpenAI-compatible HTTP clients, because they encode hard-won local-endpoint quirks (gemma hidden reasoning tokens, `max_tokens` 8192, JSON extraction). Migrating them to LangChain chat models is explicitly out of scope (optional follow-up).
- **Sync vs. async execution**: `api/services/query.py` deliberately uses a sync generator so Starlette runs it on the threadpool. *Assumption*: keep the whole graph synchronous (`graph.stream(...)`, sync node functions). No `async` migration in this plan.
- **Parallel specialist fan-out**: LangGraph's `Send` API could run independent sub-questions concurrently, but today's sequential execution is what makes the committed evaluation artifacts (`docs/evaluation/e2e-evaluation.{md,json}`) byte-reproducible, and dependent consumers are seeded from producers' harvested join IDs. *Assumption*: preserve strictly sequential, `execution_order()`-driven semantics in this migration. Whether to later enable `Send`-based parallelism (which changes result ordering, timings, and the committed eval baselines) — **Human intervention is needed to answer this question.**
- **Checkpointing/persistence scope**: LangGraph checkpointers enable resume/time-travel but Ariadne queries are short-lived request-scoped runs. *Assumption*: compile with an optional in-memory checkpointer behind an env flag (`ORCH_CHECKPOINTER`, default off); no SQLite/Postgres persistence.
- **`langgraph.json` / LangGraph Studio**: *Assumption*: ship a root `langgraph.json` registering the compiled top-level graph so `langgraph dev` visual debugging works locally, but the app launcher stays `python app.py` — no LangGraph Platform deployment.
- **Fate of `utils/specialists/pipeline.py`**: *Assumption*: the new `utils/orchestration/` package becomes canonical; `pipeline.py` is reduced to a re-export shim (deprecation docstring) for one cycle so external notebooks/scripts don't break, and all in-repo consumers are cut over to import from `utils/orchestration`.
- **LangSmith tracing**: *Assumption*: not enabled; document that setting the standard `LANGSMITH_*` env vars opts in, and ensure the LLM-off deterministic build never requires network access.

## 3. Hierarchical Step-by-Step Instructions

### Step 1: Dependencies + orchestration package scaffold
- **Locations**: `pyproject.toml` (add `langgraph>=1.0`, `langchain-core`); new package `utils/orchestration/` with `__init__.py`, `config.py` (env-driven `OrchestrationConfig`: checkpointer flag, recursion limit, timeout passthrough of `PIPELINE_TIMEOUT_S`), empty subpackages `utils/orchestration/agents/{planner,specialists,synthesis}/` and `utils/orchestration/tests/`; `.env.example` (new `ORCH_*` block).
- **Rationale**: Everything downstream imports from this package. Doing dependency addition alone first proves `uv sync` resolves LangGraph cleanly on Python 3.13 and that importing `langgraph` doesn't perturb any existing test (the full suite must still pass with the dependency merely installed). The layout mirrors the repo's own LangGraph structure reference (`docs/skills/repository-structure/structures/langgraph.md`): wiring, nodes, and state kept separate per agent.
- **Action**: Undergo the verification/tests/validation process for this phase (full `uv run python -m pytest` regression green with the new dependency installed; smoke-test `import langgraph`). Once validated, append the changelog entry and commit stating: *LangGraph Migration (1/8) Complete: Added langgraph/langchain-core dependencies and scaffolded the utils/orchestration package.*

### Step 2: Shared graph state schemas
- **Locations**: `utils/orchestration/state.py` — `PipelineState` (TypedDict with reducers) carrying: `question`, `mode`, `use_llm`, `live_view`, `plan`, accumulating `results: Annotated[list[SpecialistResult], add]`, `skipped`, `sequencing`, `by_id`, `evidence`, `answer`, `status`, `exit_code`, `timings`, `deadline`; plus `PlanningState` (request, feedback, iteration, trace, last_plan, live_view) for the planner subgraph and `SynthesisState` (evidence, draft answer, narrative, verified answer) for the synthesis subgraph. A small `utils/orchestration/serde.py` if the checkpointer needs custom (de)serialization of the existing dataclasses.
- **Rationale**: State is LangGraph's core seam and must be designed before any node exists. Critically, the state *wraps* the existing frozen contracts (`utils/planner/schema.Plan`, `utils/specialists/contracts.SpecialistResult`, `utils/specialists/federation.FederatedEvidence`, `utils/synthesis/contracts.SynthesizedAnswer`) rather than redefining them — 98 test modules and the SSE/`to_dict()` JSON contracts depend on those shapes.
- **Action**: Undergo the verification/tests/validation process for this phase (new unit tests in `utils/orchestration/tests/test_state.py` covering reducer accumulation and round-tripping the real dataclasses through the state; full regression green). Once validated, append the changelog entry and commit stating: *LangGraph Migration (2/8) Complete: Defined the shared PipelineState/PlanningState/SynthesisState schemas over the existing contracts.*

### Step 3: Planner agent as a LangGraph subgraph
- **Locations**: `utils/orchestration/agents/planner/nodes.py` (`draft_plan` wrapping the selected `PlanDrafter` from `utils/planner/drafter_factory.select_drafter`, `gate_plan` wrapping `utils/planner/gate.evaluate`, `degrade_plan` wrapping the honest-partial logic currently in `PlanningAgent._degrade`), `utils/orchestration/agents/planner/graph.py` (StateGraph over `PlanningState`: `draft → gate`, conditional edge from `gate` → `END` on pass, → `draft` with feedback while `iteration < max_iterations`, → `degrade → END` on exhaustion). Refactor `utils/planner/agent.py::PlanningAgent.plan` to delegate to the compiled subgraph while keeping its signature, `cards`/`live_sources()` accessors, and the exact `trace` dict format.
- **Rationale**: The planner's bounded self-evaluating ReAct loop is precisely LangGraph's conditional-loop idiom, making it the natural first agent to convert. Keeping `PlanningAgent` as the facade means `utils/planner/tests/test_agent_loop.py`, the evaluation drivers, and `iter_pipeline` all remain untouched while the loop's engine changes underneath — converged, revised, and degraded paths must produce identical `Plan` objects (including `trace` and `partial`).
- **Action**: Undergo the verification/tests/validation process for this phase (new `utils/orchestration/tests/test_planner_graph.py` covering converge-on-iteration-1, revise-then-converge, and degrade paths with fixture drafters; all existing `utils/planner/tests/` green unmodified). Once validated, append the changelog entry and commit stating: *LangGraph Migration (3/8) Complete: Planner draft→gate→revise/degrade loop now runs as a LangGraph subgraph behind the unchanged PlanningAgent facade.*

### Step 4: Specialist execution as graph nodes with dependency routing
- **Locations**: `utils/orchestration/agents/specialists/nodes.py` — `route_next_sub_question` (drives `utils/specialists/federation.execution_order`/`dependency_map` from state, decides run vs. skip), `run_specialist` (resolves the specialist via `utils/specialists.build_specialist` + `_specialist_for` logic, harvests seeds via `harvest_seed_ids`, emits dependency-skip results via `dependency_skip_result`, records per-specialist timings), plus deadline enforcement (skip honestly when past `deadline`, mirroring today's `PIPELINE_TIMEOUT_S` behavior); `utils/orchestration/agents/specialists/graph.py` — a sequential loop subgraph over `PipelineState` (conditional edge: more sub-questions → `run_specialist`, else → `END`).
- **Rationale**: This is the highest-risk stage: producer→consumer seeding, dependency skips, timeout skips, and `specialist-start`-before-blocking-call ordering are all analyst-facing honesty guarantees with golden tests (`utils/specialists/tests/test_pipeline.py`, `test_loop.py`, `test_golden_federated.py`, `test_latency.py`). Modeling the loop as a conditional-edge cycle (not `Send` fan-out) preserves the deterministic sequential semantics the committed eval artifacts depend on, per the §2 assumption.
- **Action**: Undergo the verification/tests/validation process for this phase (new `utils/orchestration/tests/test_specialists_graph.py` with injected fake specialists covering: dependency order, seed propagation, producer-failed skip, no-join-values skip, timeout skip, per-specialist timings; existing specialist unit tests green). Once validated, append the changelog entry and commit stating: *LangGraph Migration (4/8) Complete: Specialist sequencing, seeding, and timeout-skip logic now runs as a LangGraph subgraph.*

### Step 5: Synthesis as a LangGraph subgraph
- **Locations**: `utils/orchestration/agents/synthesis/nodes.py` (`compose_claims` wrapping `utils/synthesis/composer.DeterministicComposer`, `narrate` wrapping `utils/synthesis/narrator.compose_narrative` best-effort when `llm_enabled`, `verify` wrapping `utils/synthesis/verifier.verify_answer` — always run, never conditional), `utils/orchestration/agents/synthesis/graph.py` (linear `compose → narrate → verify` over `SynthesisState`, `narrate` internally no-op when LLM disabled). Refactor `utils/synthesis/factory.synthesize` to delegate to the compiled subgraph, preserving its signature, fallback-reason recording, and `SynthesizedAnswer` output (claims, edges, narrative, verification) byte-for-byte in LLM-off mode.
- **Rationale**: The current `synthesize()` already sequences deterministic claims → LLM narrative → mandatory verification (per the 2026-07-08 changelog entries); making those three explicit nodes preserves the invariant "the verifier is not optional" *structurally* — it's an unconditional edge, not a code path. Keeping the facade keeps `utils/synthesis/tests/` (136 tests) and `score_e2e` untouched.
- **Action**: Undergo the verification/tests/validation process for this phase (new `utils/orchestration/tests/test_synthesis_graph.py` covering LLM-on narrative, LLM-off deterministic narrative, and verifier-always-runs; all existing synthesis tests green unmodified). Once validated, append the changelog entry and commit stating: *LangGraph Migration (5/8) Complete: Synthesis compose→narrate→verify now runs as a LangGraph subgraph behind the unchanged synthesize() facade.*

### Step 6: Top-level pipeline graph + streaming adapter (the cutover)
- **Locations**: `utils/orchestration/main.py` — the super-graph over `PipelineState`: `check_cards → probe → plan (Step 3 subgraph) →` conditional (`mode == "plan"` → `finalize_plan_only`; else → specialists subgraph from Step 4) `→ bundle` (wrapping `bundle_evidence` + `status_and_exit`) `→ synthesize (Step 5 subgraph) → finalize`; every node emits the existing event vocabulary — `status`, `probe`, `plan`, `skipped`, `specialist-start`, `specialist`, `evidence`, `answer`, `done` — through `langgraph.config.get_stream_writer()`. Rewrite `utils/specialists/pipeline.py`: `iter_pipeline` becomes a thin adapter that compiles/streams the graph with `stream_mode="custom"` and yields the same `(event, payload)` tuples with the same raw-object payloads; `run_pipeline` and `PipelineRun` (including `timings` keys `plan_ms`, `specialists[]`, `synthesis_ms`, `total_ms`) keep their exact shapes; `pipeline_timeout_s` and the no-cards early-exit message are preserved verbatim.
- **Rationale**: This is the moment LangGraph becomes the real orchestrator. The event stream is a load-bearing public contract — `api/services/query.py` shapes it into SSE, the web UI animates phases off `status`/`specialist-start`, and the CLI prints it — so the adapter must reproduce ordering exactly (notably `specialist-start` firing *before* the blocking specialist call, and `answer` preceding `done`). A dedicated parity test locks this in.
- **Action**: Undergo the verification/tests/validation process for this phase (new `utils/orchestration/tests/test_event_parity.py` — golden event-sequence test asserting the full `(event, payload-shape)` order for query mode, plan mode, no-cards, dependency-skip, and timeout scenarios matches the pre-migration contract; `utils/specialists/tests/test_pipeline.py` and `api/tests/` green **unmodified** — those tests are the contract). Once validated, append the changelog entry and commit stating: *LangGraph Migration (6/8) Complete: iter_pipeline now streams the compiled LangGraph super-graph with byte-identical event contract.*

### Step 7: Consumer cutover, langgraph.json, checkpointing & observability
- **Locations**: `api/services/query.py` and `utils/specialists/cli.py` import from `utils/orchestration` (with `utils/specialists/pipeline.py` left as a documented re-export shim); evaluation drivers (`utils/evaluation/score_e2e.py` live drivers) confirmed on the same path; root `langgraph.json` registering `utils/orchestration/main.py`'s compiled graph for `langgraph dev` inspection; `utils/orchestration/config.py` gains the optional `InMemorySaver` checkpointer flag (`ORCH_CHECKPOINTER`, default off, `thread_id` = one per query run); `api/services/config.py` + `api/models.py` + `.env.example` expose the new `ORCH_*` group in the settings UI, following the pattern used for the four LLM groups.
- **Rationale**: Cutting consumers over makes `utils/orchestration` the single canonical composition (the same drift-prevention argument that created `pipeline.py`); `langgraph.json` gives the team the visual graph debugger for free; checkpointing stays opt-in so request-scoped query latency and determinism are unaffected by default.
- **Action**: Undergo the verification/tests/validation process for this phase (all `api/tests/` contract tests green; `cd web && npm run lint && npm run build && npm test` green — required since the settings UI changes; manual `python app.py` smoke: one federated question streamed end-to-end in the workbench with live phase labels advancing). Once validated, append the changelog entry and commit stating: *LangGraph Migration (7/8) Complete: API/CLI/eval consumers cut over to utils/orchestration; langgraph.json, optional checkpointer, and ORCH_* config group added.*

### Step 8: Full regression, live goldens, evaluation artifact regeneration & docs
- **Locations**: Full backend suite (`uv run python -m pytest` including `live` golden tests against the Docker stack — wipe + reload live Neo4j/Gremlin first via `uv run main.py --docker start` + `--graph` loaders, per the live-fixture-reload requirement); regenerate `docs/evaluation/e2e-evaluation.{md,json}` via `uv run main.py --e2e-eval` and verify the LLM-off run is byte-identical to the committed baseline (any diff is a regression to fix, not commit); docs — `docs/structure.md` (utils/orchestration package, LangGraph as orchestrator, pipeline.py shim status), `README.md` (architecture blurb + dependency), `docs/goals.md` if the roadmap references orchestration, and `docs/skills/repository-structure/SKILL.md` if the repo map table needs the new package row.
- **Rationale**: The committed e2e baseline (120 cases, all four metrics at ceiling) is the citable proof the migration changed *how* the pipeline is orchestrated without changing *what* it answers; byte-identical regeneration is the strongest possible equivalence check. Docs are the project's source of truth and must not advertise the old custom orchestrator after it's gone.
- **Action**: Undergo the verification/tests/validation process for this phase (full backend regression ~1,035+ tests green including live goldens; e2e eval artifacts byte-identical in LLM-off mode; web lint/build/test green). Once validated, append the changelog entry and commit stating: *LangGraph Migration (8/8) Complete: Full regression and live goldens green, e2e evaluation baseline reproduced byte-identical, docs updated to reflect the LangGraph orchestrator.*
