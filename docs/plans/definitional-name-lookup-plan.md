# Definitional Name-Lookup Plan

## 1. Introduction

Today a question that names an entity by its human name and asks for its definition — e.g. *"What exactly is User Training and Software Configuration respectively?"* — returns "The provided evidence does not contain any information to answer the request," even though the graph holds a `Mitigation` node named *User Training* (M1017) with a full `description`. The cause is structural: retrieval anchors only on canonical ids (`attack_id`, CAPEC/CWE ids) extracted by regex in `utils/specialists/resolve.py`, and every builder template filters on `attack_id IN $ids`. A name like "User Training" produces no id, so no seed is extracted, no query is emitted, zero records come back, and synthesis honestly (but misleadingly) abstains. Separately, the just-shipped **Entity Dossier** feature already returns exactly the description + typed 1-hop output we want — but it is gated on an id seed *and* a describe-intent regex that "What is X?" does not even match, so definitional-by-name questions never reach it. Finally, when nothing resolves, the abstention text shown to the analyst is free-text authored by the local planner model (the observed *"The request 'What' is incomplete"*), not a clear, deterministic message.

This plan adds a **name → dossier** front-end that reuses the existing dossier normalizer and memory formatters, plus a **clear deterministic abstention** for genuine misses. Deterministic name-term extraction (quoted phrases and Title-Case runs) feeds new name-anchored dossier templates in both the Cypher and Gremlin builders; the planner learns to route definitional questions to the live sources so those templates fire on the first pass (LLM-on and LLM-off); and the synthesis layer replaces the garbled "unsupported" surfacing with an honest, actionable "couldn't find X — did you mean …" message. Every new behavior is deterministic and validator-safe, and each step lands as its own tested, committed unit — committed locally, never pushed.

## 2. Gaps & Unanswered Questions

- **Multi-word names from unquoted text** ("User Training", "Software Configuration"): the existing tokenizer splits on words, losing the phrase. *Assumption*: extract name terms in priority order — (1) quoted phrases, (2) Title-Case runs (one or more consecutive Capitalized words, ignoring a leading sentence-initial capital that is a stopword like "What"), (3) filtered free-text tokens (stopwords, card label/relationship identifier tokens, scaffold vocabulary, id-shaped patterns removed; min length 4; capped at 4 terms). Match case-insensitively against `toLower(node.name)`.
- **Which labels are "description-bearing"** for a name match: *Assumption*: match across the ATT&CK labels that carry `name` + `description` (Mitigation, Technique, SubTechnique, Tactic, Group, Software, Campaign, DataComponent, DetectionStrategy) via an explicit multi-label `OR` guard — never a bare unlabeled scan, which the validator rejects — and, on the CAPEC side, `AttackPattern`. The label set is derived from the source card at build time, not hardcoded, so it tracks the schema.
- **Exact vs. fuzzy match**: *Assumption*: exact case-insensitive full-phrase match first (`toLower(n.name) IN $names`); if a name term does not match exactly, fall back to a bounded `CONTAINS` scan on the same term. Precision first, recall second, always under the injected `LIMIT`.
- **Ambiguous names** (a term matching several nodes): *Assumption*: return every match up to `LIMIT`; the answer agent already summarizes multiple entities, and the analyst sees each candidate with its id.
- **Which source to route a bare name to** (ATT&CK or CAPEC is unknown from a name alone): *Assumption*: a definitional question with name terms routes a join-free name-lookup sub-question to **every live source**; the matching source returns the dossier, the other returns empty and is suppressed by the new abstention logic. No cross-source join is declared for definitional lookups.
- **Regression risk in the deterministic drafter**: the definitional bridge must not perturb existing keyword routing. *Assumption*: the bridge fires only when `is_definitional_intent` is true **and** name terms exist, and it short-circuits the normal keyword/join path for that request (a purely definitional turn), leaving every non-definitional plan byte-identical.
- **Derived-artifact regeneration**: builder templates and drafter routing feed the golden banks and planner corpus, so per the concurrent-sessions rule they must be regenerated in this change and the live goldens re-run against fresh graph data (wipe+reload if stale). *Assumption*: regenerate banks + corpus here; the full component-eval report only if bank contents change.
- **Human intervention**: none identified — no step requires a human decision before implementation.

## 3. Hierarchical Step-by-Step Instructions

#### Step 1: Shared resolver — name-term extraction + definitional intent
- **Locations**: `utils/specialists/resolve.py` (`ResolvedTask` dataclass — new `name_terms` field; new `_extract_name_terms` helper called from `resolve()`; new `is_definitional_intent` predicate alongside the existing `is_dossier_intent`, recognizing "what is/are X", "what's X", "what exactly is X" in addition to the current describe verbs); `utils/specialists/tests/test_resolve.py`.
- **Rationale**: Both builders need a single deterministic, card-grounded source of name anchors, and the router/builders need to recognize a bare "what is X" as a definitional deep-dive (the current `_DOSSIER_INTENT_RE` misses it). Extraction is card-aware so schema-identifier tokens (label/relationship words) never leak in as false name anchors, mirroring how `concept_terms` already flows through `ResolvedTask` — no downstream signature changes.

#### Step 2: Cypher builder — name-anchored dossier template + routing
- **Locations**: `utils/specialists/cypher/builder.py` (new `_node_dossier_by_name` template method; a card-derived description-bearing label set; new routing branch in `CypherQueryBuilder.build` that, when there are no seed ids but `name_terms` and definitional/dossier intent are present, emits the name dossier in place of the catastrophic `_label_scan`; docstring template census bump); `utils/specialists/tests/test_cypher_specialist.py`.
- **Rationale**: This is the core retrieval fix. The template matches the description-bearing labels by case-insensitive name (exact `IN`, then a bounded `CONTAINS` fallback) and returns the **same dossier row shape** (`properties_json` + collected typed neighbors) that the existing `utils/specialists/cypher/normalizer.py` dossier path already consumes — so the description and typed 1-hop flow into `evidence_brief` with zero normalizer changes. The branch sits at the seedless fallback so seeded/by-id paths and all existing templates are untouched, and the multi-label `OR` guard + injected `LIMIT` keep it validator-safe.

#### Step 4: Planner routing — definitional questions reach a specialist
- **Locations**: `utils/planner/drafter.py` (`DeterministicDrafter.draft` — a definitional bridge, gated on a shared definitional-intent check and extracted name terms, that routes a join-free name-lookup sub-question to every live source and short-circuits the keyword/join path for that request); `utils/planner/llm_drafter.py` (`_SYSTEM_PROMPT` — permit a definition/name-lookup sub-question that names an entity by its human name and routes to the relevant live source(s), without inventing labels); `utils/planner/tests/test_deterministic_drafter.py`, `utils/planner/tests/test_llm_drafter.py` (or the existing `build_messages` test module).
- **Rationale**: Name-term extraction only helps if a sub-question actually reaches a specialist; in the reported failure the LLM path dead-ended to `unsupported` and the deterministic path mis-routed "software" to the `Software` label. Bridging definitional intent to a first-class name-lookup sub-question makes the LLM-off plan carry the scope an LLM plan would, so Step 2/3's templates fire on the first pass, and keeps plans gate-valid by construction (routes only to live sources, no fabricated labels, no unresolved join).

#### Step 5: Synthesis — clear, actionable abstention on a genuine miss

Making the abstention deterministic and specific (naming the unresolved term, and where useful suggesting the nearest matches) turns "I can't get any information" into an honest, actionable answer, and stops the weak local model's phrasing from being the user-facing message.
