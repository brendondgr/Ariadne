## 1. Non-negotiable principles

These govern every decision below. If an instruction conflicts with a principle, the principle wins.

1. **One canonical location.** `docs/research/` is the only place a research finding is allowed to live. Results in a Slack message, a notebook cell, a commit message, or a chat log do not exist.
2. **The unit of record is the experiment, not the file.** Each experiment is a directory with a fixed internal contract, not a loose markdown file dropped into a pile.
3. **Every number in the paper traces to an experiment ID.** No orphan numbers. A claim without a traceable experiment is a claim that gets cut from the paper.
   *Verified by `make verify-paper-numbers`, which you run — nothing runs it for you.*
4. **Figures are generated, never hand-placed.** Each figure has a script that produces it from recorded results. If a figure cannot be regenerated by a command, it does not go in the paper. This is the `showyourwork` philosophy — the article's figures, tables, and numbers are all built from checked-in scripts so the whole manuscript can be rebuilt from scratch.
5. **Failures are recorded with equal weight.** Negative results, crashed runs, and abandoned directions are first-class entries. They are what stops you re-running a dead end in month nine, and they populate the limitations section.
6. **Record at write-time, not at paper-time.** The pipeline writes the record; the human reviews it. Anything that depends on human diligence at the end will not happen.
7. **Append-only for completed experiments.** A finished experiment folder is immutable. Corrections go in a new experiment or an appended `AMENDMENTS` section, never a silent edit.

## 3. The experiment directory contract

Directory name: `EXP-<YYYY>-<MM>-<NNN>-<kebab-slug>`
The ID is permanent and is the only handle used in code, figures, commit messages, and paper drafts.

```
EXP-2026-08-001-baseline-retrieval/
├── manifest.yaml          # REQUIRED — machine-readable
├── PROTOCOL.md            # REQUIRED — what we did and why, written BEFORE running
├── RESULTS.md             # REQUIRED — what happened, written after
├── figures/               # REQUIRED if any figure exists
│   ├── fig-recall-at-k.svg
│   ├── fig-recall-at-k.pdf
│   └── make_figures.py    # regenerates every figure in this folder
├── tables/                # generated .md and .tex fragments
├── data/
│   ├── metrics.json       # canonical machine-readable metrics
│   ├── metrics.csv        # per-seed / per-run raw numbers
│   └── POINTERS.md        # paths + hashes for large artifacts stored elsewhere
├── env/
│   ├── requirements.lock  # or environment.yml / uv.lock / Dockerfile digest
│   └── hardware.md        # GPU/CPU, RAM, driver, wall-clock, cost
├── logs/                  # trimmed run logs or pointers to them
└── ISSUES.md              # bugs, anomalies, aborted runs, gotchas
```

### 3.1 `manifest.yaml` — required schema

This is the field's structural answer to the reproducibility crisis: hyperparameters, seeds, data version, and compute all recorded, because undocumented hyperparameters and cherry-picked seeds are exactly the documented failure modes.

```yaml
id: EXP-2026-08-001
slug: baseline-retrieval
title: Baseline retrieval performance on <dataset>
status: complete            # planned | running | complete | failed | superseded
date_started: 2026-08-06
date_completed: 2026-08-07
authors: [<name>]

purpose: >
  One paragraph. What question does this answer, and which paper claim
  does it support or refute?

hypothesis: >
  Stated before the run. If exploratory, write "exploratory — no prior hypothesis".

# --- Reproducibility block (all fields mandatory) ---
code:
  commit: a1b2c3d4
  branch: main
  entrypoint: "python -m src.eval.baseline --config configs/baseline.yaml"
  dirty: false              # were there uncommitted changes? if true, explain in ISSUES.md
config:
  path: configs/baseline.yaml
  hash: sha256:...
data:
  name: <dataset>
  version: v1.2
  split: test
  n_examples: 4821
  dvc_path: data/processed/<dataset>.dvc
  hash: md5:...
seeds: [0, 1, 2, 3, 4]
n_runs: 5
environment:
  python: "3.11.9"
  lockfile: env/requirements.lock
  container: "ghcr.io/<org>/<img>@sha256:..."
compute:
  hardware: "1x A100 80GB"
  wall_clock_hours: 2.4
  estimated_cost_usd: 12.40

# --- LLM / agentic block (omit if not applicable) ---
llm:
  model: "<provider>/<model>@<version-or-date>"
  temperature: 0.0
  top_p: 1.0
  max_tokens: 2048
  prompt_files: [prompts/extractor.md]
  prompt_hash: sha256:...
  tool_schema_hash: sha256:...
  total_input_tokens: 1842301
  total_output_tokens: 233104
  nondeterminism_note: >
    Provider-side nondeterminism remains even at temperature 0; results
    are reported as mean ± std over n_runs.

# --- Results block ---
metrics:
  primary: recall@10
  values:
    recall@10: {mean: 0.612, std: 0.008, n: 5}
    ndcg@10:   {mean: 0.441, std: 0.011, n: 5}
  withdrawn:                       # values this experiment once reported and has retracted (2026-09-09)
    recall@10_first_pass:
      mean: 0.587
      std: null
      n: 5
      withdrawn_on: 2026-08-31
      reason: "graded by an unidentified model; recomputed in A-1"
      replaced_by: "EXP-2026-08-001:recall@10"   # <EXP-ID>:<metric key>, or "none"
baselines_compared: [BM25, dense-e5]
statistical_test: "paired bootstrap, 10k resamples, p=0.03"

# --- Linkage ---
supports_claims: [C-003, C-004]
figures: [fig-recall-at-k]
supersedes: null
superseded_by: null
related: [EXP-2026-07-004]
```

**Field definitions that were ambiguous until 2026-09-09.**

- `n_runs` counts **system runs** — how many times the pipeline under test was executed over the question set. Grading passes, grading positions and re-grades are *not* runs; record them in `statistical_test` or in the metric's own `n`. An LLM-free arm that was executed once has `n_runs: 1` even if it was graded five times.
- `metrics.withdrawn` holds every value the experiment once reported in `metrics.values` and has since retracted by amendment. **A withdrawn value is moved, never deleted**, and `replaced_by` names the quotable figure. `CURRENT.md` lists every withdrawn value, and `make check-docs` fails on prose that quotes one as current.
- `supersedes` / `superseded_by` are recorded in **both** manifests or in neither. `status: superseded` means the whole headline is replaced by the successor; an experiment merely *refined* by a later one stays `complete` and lists the later ID in `related`.

### 3.2 `PROTOCOL.md` — written *before* the run

Sections, in order: **Question · Hypothesis · Setup · Data · Metrics (defined, not just named) · Baselines · Procedure (exact commands) · What would falsify this**.

Pre-registering the protocol is what separates an experiment from a fishing expedition. It also means the methods section is already half-written.

### 3.3 `RESULTS.md` — written *after* the run

Sections, in order:

1. **Headline** — two sentences. The number and whether the hypothesis survived.
2. **Results table** — generated, not typed. Mean ± std across seeds, never a single run.
3. **Figures** — embedded with a one-line caption each, referencing the generating script.
4. **Interpretation** — what it means for the paper's argument.
5. **Threats to validity** — confounds, leakage risks, dataset artifacts, cost of the comparison.
6. **What surprised us** — the section that becomes the discussion section.
7. **Follow-ups** — each one becomes an entry in `OPEN_QUESTIONS.md`.
8. **Reproduction** — the exact command that regenerates everything in this folder.

### 3.4 Failed and abandoned experiments

They stay. Set `status: failed` or `superseded`, fill `RESULTS.md` with what broke and why, and never delete the directory. A deleted failed experiment is a dead end you will walk into twice.

## 4. Figure standards

The single most common way research repositories rot is figures pasted from a notebook that nobody can regenerate after the axis label turns out to be wrong.

**Rules:**

- Every figure has a generating script committed beside it. One command regenerates all figures in an experiment.
- Output **both** `.svg` (vector, editable, diffable, web-embeddable) and `.pdf` (for LaTeX). Raster `.png` only for genuine bitmaps like heatmap screenshots or qualitative examples — and even then, keep the generator.
- Figures read metrics from `data/metrics.json` or `metrics.csv`. Never from hardcoded numbers in the plotting script.
- Filename = `fig-<slug>.<ext>`, matching the `figures:` list in `manifest.yaml`.
- Fonts embedded; no font smaller than 7pt at final print size; colour-blind-safe palette; no colour-only encoding.
- Architecture and system diagrams are authored as SVG (hand-written or via a diagram-as-code tool such as Mermaid, Graphviz, or TikZ) and committed with their source. Binary-only diagram exports are rejected.
- **Promotion:** a figure only moves to `docs/research/figures/` when it is destined for the paper. Promotion copies the figure *and* its generator into `figures/sources/`, and records the source experiment ID in a header comment.

Add a `make figures` (or `just figures`) target that regenerates every promoted figure from scratch. Run it in CI. If it fails, the figures are stale.

## 5. Cross-cutting ledgers

### `INDEX.md` — auto-generated, never hand-edited

A script walks `experiments/*/manifest.yaml` and emits a table: ID · date · title · status · primary metric · claims supported · link. Regenerate on pre-commit and in CI. Hand-maintained indexes go stale within three weeks.

### `CURRENT.md` — auto-generated, never hand-edited (added 2026-09-09)

Generated with `INDEX.md` by `make index`. Three tables from the manifests: every withdrawn value with its replacement, every superseded experiment with its successor, and one current headline per experiment that is still the latest word. **Read it before quoting any number.** It cannot drift from the manifests because it is derived from them.

### `CLAIMS.md` — the paper's spine

| ID | Claim (as it will appear in the paper) | Evidence (EXP IDs) | Artifact (fig/table) | Status |
|----|----------------------------------------|--------------------|----------------------|--------|
| C-001 | Federated KG construction improves entity coverage over single-agent extraction | EXP-2026-08-002, EXP-2026-08-005 | fig02, tab01 | supported |
| C-002 | ... | — | — | **unsupported — needs experiment** |

This table is the highest-value artifact in the whole directory. It tells you, at a glance, which claims you can actually make and which are currently vapour. Write claims *before* they are supported and mark them unsupported — that is your experiment backlog.

### `DECISIONS.md` — ADR-style, dated, append-only

One entry per research decision: **Context · Options considered · Decision · Consequences · Date**. Covers metric choices, baseline selection, dataset exclusions, scope cuts. Reviewers ask "why did you use X?" — this is where the honest answer already lives.

### `RELATED_WORK.md`

Running bibliography with a one-line "how it differs from us" per entry, plus a **scoop watch** section for papers that partially overlap your contribution. Update it whenever a relevant paper surfaces, not the week before submission.

### `OPEN_QUESTIONS.md`

Every follow-up from every `RESULTS.md`, plus known weaknesses. This becomes future work and pre-empts reviewer objections. An answered question moves verbatim to `OPEN_QUESTIONS-ANSWERED.md` with the date and the experiment or decision that answered it, so the live file holds only what is open.

### `CLAIMS-HISTORY.md`

`CLAIMS.md` holds one short row per claim with the *current* figure. Every earlier version of a row, with its layered updates, lives verbatim under the claim's ID in `CLAIMS-HISTORY.md`, append-only. The first number a reader meets in `CLAIMS.md` is therefore always the newest.

## 7. Automation and enforcement

Convention without enforcement decays. Implement all four:

**7.1 Scaffolding.** `scripts/new_experiment.py` (+ `make new-experiment SLUG=...`): allocates the next ID, copies `templates/experiment/`, pre-fills date, git commit, branch, and dirty-tree status.

**7.2 Auto-capture at run time.** A small `research_record` helper (or existing tracker — MLflow, W&B, DVCLive) that, on every evaluation run, writes git commit, config hash, data version/hash, seeds, environment lockfile, hardware, wall-clock, and final metrics straight into the experiment's `manifest.yaml` and `data/metrics.json`. The tracker's job is capture; `docs/research/` is the durable, human-readable, git-tracked mirror. If you use MLflow or W&B, still export a static snapshot into the experiment folder — external dashboards die, repositories persist.

**7.3 Validation.** `scripts/validate_research.py` (+ `make validate-research`), failing on:
- missing `manifest.yaml`, `PROTOCOL.md`, or `RESULTS.md`
- manifest failing schema validation (use a JSON Schema or Pydantic model)
- `status: complete` with empty `metrics.values`
- a figure listed in the manifest that has no file, or a figure file not listed
- a figure without a generating script in the same folder
- any `data/` artifact pointer without a hash
- a `supports_claims` ID absent from `CLAIMS.md`
- a stale `INDEX.md` or `CURRENT.md`
- **(added 2026-09-09)** a terminal experiment with `date_completed: null`, or completed before it started
- **(added 2026-09-09)** a scaffold placeholder (`<...>`) surviving in a terminal manifest
- **(added 2026-09-09)** a terminal experiment whose `data/POINTERS.md` table is empty and does not state "no external artifacts"
- **(added 2026-09-09)** a terminal experiment without `data/metrics.json`, or whose manifest carries a number that appears nowhere in it
- **(added 2026-09-09)** a `supersedes` / `superseded_by` link recorded in only one of the two manifests, a link to an experiment not on record, or `status: superseded` with no successor
- **(added 2026-09-09)** a pointer whose path exists and whose hash no longer matches (absent paths are skipped, because raw run output is gitignored and a fresh clone must still validate)

The first eight were installed on 6 August 2026. The last six were added after a
full audit on 2026-09-09 found the first eight passing on 47 experiments of
which thirteen carried blank contract files, impossible commits, or values
their own amendments had withdrawn.

**7.4 CI.** There is no CI in this repository (see `OPEN_QUESTIONS-ANSWERED.md`, Q32). The pre-commit hook (7.5) and `make check-record` are the gate. Building CI remains open work.

**7.5 Pre-commit hook.** `scripts/install_hooks.sh` installs it. On every commit: a changelog `summary` over 600 characters is rejected. On a commit touching `README.md` or `docs/`: `scripts/verify_paper_numbers.py --docs --gate` fails the commit if any prose document quotes a withdrawn or superseded figure. On a commit touching `docs/research/`: `INDEX.md` and `CURRENT.md` are regenerated and staged, and the validator runs on every touched experiment folder.

**7.6 `.gitattributes` / `.gitignore`.** SVG and small JSON/CSV in git. Checkpoints, large parquet, and raw logs to DVC or LFS. Nothing above ~10 MB enters `docs/research/`.

## 8. Publication alignment

Bake the venue requirements in from day one rather than scrambling at submission.

- **`paper/checklists/`** — commit the reproducibility checklist for each target venue and treat it as a live to-do. These checklists ask for datasets, hyperparameters and the ranges searched, number of runs and seeds, metric definitions, and compute infrastructure. Every one of those fields is already a manifest field, by design.
- **`paper/venue-targets.md`** — deadline, page limit, anonymisation policy, artifact-evaluation track, supplementary limits.
- **Artifact evaluation.** Most ACM/USENIX venues award three badges: *Available* (artifact deposited in a public archival repository), *Functional* (documented, consistent, complete, exercisable), and *Results Reproduced* (an independent committee re-obtains the main results within tolerance). Note that GitHub alone does not satisfy *Available* — an archival DOI from Zenodo, Figshare, or Dryad is required. Add `paper/ARTIFACT_APPENDIX.md` early; the appendix is typically ~2 pages and mostly assembles from `manifest.yaml` + `PROTOCOL.md`.
- **Research compendium framing.** The end state is a single container holding the article, the analysis, the data, and the environment — that is the standard the repository should be able to become with one archival push, not a restructuring project.
