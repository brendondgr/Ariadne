# PROTOCOL — EXP-2026-11-006 Typed request format v3 on three benchmarks

Written 2026-11-14, before any part-C generation and before any part-C question was read.
- **Format v3** was designed from EXP-2026-11-005's part-B analysis, its Text2Cypher gap list.
- **The third benchmark** was chosen and selected mechanically from dataset cards, schemas and
  counts only. No question or gold query of it has been read.

## Questions

- **Part A (CypherBench, 200; regression and record check):** does v3 keep v2's accuracy on the
  benchmark the format was designed from? Every arm is rerun with Qwen at `reasoning_effort=medium`,
  so all of Qwen's figures use one setting. (EXP-2026-11-003/-004 used the server default `xhigh`.)
- **Part B (Text2Cypher, 390; development check):** do the v3 fixes work on the benchmark they
  were designed from?
  - Same questions as EXP-2026-11-005.
  - This is **not** evidence of generalisation, because v3 was built from this benchmark's gaps.
- **Part C (Mind the Query, 450; held out, the kill test):** on a benchmark the format was never
  shaped by, do typed v3 requests beat free Gremlin, stay close to free Cypher, and agree across
  backends?

## Format v3 (`utils/killtests/typed/request.py`, `cypher.py`, `gremlin.py`)

A superset of v2: every v2 request means the same in v3, except that `top` now breaks ties by the
key property ascending (both backends; v2 left ties to the engine). Additions:

1. **`per`**: for each `n`, `count` of distinct `of`, or `sum`/`avg`/`max`/`min` of `of`'s property,
   where `of` is a node or an edge var. It takes optional `having` (a threshold on the value) and
   `order` + `limit`, with ties broken by `n`'s key ascending and Cypher's null ordering.
   `count_per` becomes `per` with `fn: count`.
2. **`top`** takes optional `props` (extra columns).
3. **Edge references** (`var` names of edges in `edges`) are accepted in `optional` and in the new
   `none`, as in `any_of`.
4. **`none`**: one edge from `n` that must not exist (`NOT EXISTS` / `.not(...)`), with filters on
   its far node.
5. **`ref`**: a filter compares a property with another property instead of a value.
6. **`part: "size"`**: compares the number of elements of a list property.
7. **Numbers stored as text** (card type `float_text`): compared, sorted and aggregated as numbers
   (`toFloat` / `asNumber(GType.DOUBLE)`).
   - The card marks a string property `float_text` when every sampled value parses as a number,
     at least 10% contain a decimal point, and it is not the key.
   - The card's key rule now also accepts identifier-like properties of any type, e.g. an integer
     `primaryid`. On the Text2Cypher graphs this changes no key; it adds `float_text` to
     northwind's `Order.freight` and fincen's four latitude/longitude fields.

**Verification before the run** (`logs/killtests-2026-11/typed-verify-v3/`):
- **Differential:** 6,000 random v3 requests on the synthetic graph agree on Cypher and Gremlin
  for **1.000**; 82% are non-empty. Every new feature is exercised hundreds of times; `per` alone
  appears in 2,683 requests.
- **Gold:** on CypherBench terrorist_attack training questions, 0.9986 on both backends among the
  1,439 with runnable gold, with backends agreeing on 1.000.
  - v2 scored Cypher 1.000. Two argmax questions now fail on Cypher as well as Gremlin.
  - Both are ties at the extreme value (checked): the gold kept Neo4j's arbitrary pick, and v3
    breaks ties by name.

## Part C data: Mind the Query, manually validated test split

- **Source:** endeavorXx/Mind-the-Query (EMNLP 2025 Industry track), Apache-2.0, commit `ec4054a1`.
  - The gold Cypher was generated by Gemini, then judged by two annotators and an arbiter.
  - The questions are LLM-written.
- **Graphs:** the authors' Neo4j dumps of WWC (2,486 nodes / 14,799 relationships), healthcare
  (11,381 / 61,453) and entity resolution (`er`, 1,237 / 1,819).
  - Each is restored into its own Neo4j (`mtq-<g>-neo4j`, bolt 5511–5513) and mirrored into its
    own TinkerGraph (6511–6513).
  - Parity is exact: labels, relationship counts, and 50 sampled nodes per graph.
  - Every node has exactly one label.
- **Excluded graphs:**
  - Bloom: one node carries two labels, and the test split has only 55 judged rows.
  - covid: almost no rows judged.
  - The other graphs have no manual test split.
- **Selection** (`gold.select_mtq`, mechanical):
  1. Test-split rows judged logically correct (`logical [0/1]` = 1), deduplicated.
  2. The same filters as EXP-2026-11-005: runs, returns rows, scalar values only, no LIMIT
     without ORDER BY.
  3. A seeded sample (20261114) of 150 per graph.

  | | Count |
  |---|---|
  | Eligible after filters | wwc 379, healthcare 251, er 328 |
  | **Selected** | **450** |
  | Excluded: not judged logical | 81 |
  | Excluded: gold empty on the dump | 277 |
  | Excluded: gold error | 17 |

  Of the 450: 224 come from the "Complex Aggregation" set and 226 from "Complex Retrieval".
- **Cards:** the same reader as Text2Cypher (`t2c/load.py`), v3 rules. All keys are chosen from
  the schema alone:
  - healthcare's `Case` and `Therapy` key on `primaryid`;
  - er's `User` on `userId`;
  - wwc's `Match` and `Squad` on `id`.

## Arms and models

- **Models:** identified by tokenizer token ids at the start of every pass.
  - Gemma 4 31B: server default; it has no reasoning setting.
  - **Qwen 3.8 27B at `reasoning_effort=medium`, in every part.**
  - Temperature 0, max tokens 8,192, 16 concurrent requests per model.
- **Arms, in every part, at 3 shots:**
  - `cypher-3shot` and `gremlin-3shot` (free);
  - `typed2-3shot` (v2 format text);
  - `typed3-3shot` (v3 format text);
  - `typed3-3shot-repair`: one more turn showing the validator's message, for invalid or
    unparseable `typed3-3shot` replies. It is secondary and in no rule.
- **Prompt content:** every arm sees the same three worked examples as T1 and the same schema block.
  - Text2Cypher and Mind the Query use the v3 card block, which writes `float_text` as
    "float_text (a number stored as text)".
  - 0-shot arms are not run.
- **Scorer:** exact records, the pre-registered scorer of EXP-2026-11-003–005.
- **Freeze:** no change to the format, compilers, cards, prompts or selection after this protocol
  is committed (tag `killtests-exp006-run`).

## Hypotheses and kill rule

**Part C** (the kill test), for each model, at 3-shot:
- **H1 (backend independence):** typed3 via Cypher and via Gremlin differ by ≤ 0.02.
- **H2:** typed3 via Gremlin ≥ free Gremlin + 0.10.
- **H3:** typed3 via Cypher ≥ free Cypher − 0.05.

**Kill:** H2 fails for any model, **or** H3 fails for every model. H1 failing is a compiler
defect, recorded in ISSUES.md.

The primary metric is `C_typed3_3shot_gremlin_minus_free_gremlin_3shot`, per model, with a paired
bootstrap 95% CI.

**Part B** (expectations, not a kill test; development data):
- **B1:** typed3 ≥ typed2 + 0.10 for each model.
- **B2:** H2 and H3 as above, reported only.

**Part A** (expectations):
- **A1:** typed3 ≥ typed2 − 0.02 for each model.
- **A2:** Qwen's free arms at `medium` are reported beside its earlier `xhigh` figures; no
  hypothesis.

## Secondary, exploratory

- **Lenient rescoring** of every arm in B and C, as EXP-2026-11-005 §4.2:
  - duplicates ignored;
  - column subsets allowed;
  - known to over-credit occasionally.
- **Results by graph and by source.**
- **Coverage on part C, after the run:** a seeded random sample of 40 part-C questions, judged by
  hand for "expressible in v3". It is labelled post hoc.
- **typed3 minus typed2 on part C:** what the v3 additions buy on unseen questions.

## Known limits, stated before the run

- **Mind the Query's questions are LLM-written.** Its gold was judged by people, but not written
  by them.
- **Some gold queries return extra columns.** The strict scorer penalises every arm for this;
  rescoring is the secondary check.
- **v3 was designed from Text2Cypher's gaps,** so part B cannot show generalisation; part C can.
- **Qwen's figures at `medium` are not like for like with its `xhigh` figures** in earlier
  experiments. Part A gives the comparison.
- **Gemma hits the 8,192-token cap.**
  - In the smoke run, every unparseable typed reply (5 of 48 typed generations in B and C) was
    Gemma reaching the cap before writing any JSON.
  - In EXP-2026-11-005 Gemma also capped on 71 free-Gremlin and 31 typed replies.
  - Gemma's server exposes no reasoning setting, so the cap stays as it is, the same for every arm.
- **The smoke run** (3 questions per part, `logs/killtests-2026-11/exp006-smoke/`) checked only
  statuses, errors and backend agreement for parts B and C. Its part-C content and scores were
  not read.
