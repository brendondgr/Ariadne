# RESULTS — EXP-2026-09-022

## Headline

Pooled lexical discovery reaches T4 anchor recall@10
**0.5705** and T5 **0.7901**;
separate-field fusion is worse on both, and the graph-context arm does not beat
pooled search at that budget. These are **candidate discovery results**, not improved answers:
the prototype neither selects an accepted anchor nor executes an answer query.

The exploratory run supplies evidence for testing retrieval plus careful
reranking, and no evidence for adopting these equal-weight fusion mechanisms.
It changes no workbench setting and does not establish a production improvement.

## Interpretation

**Discovery is possible before acceptance is solved.** Pooled top-1 coverage is
only 0.1683 at T4 and
0.3157 at T5. Its higher top-10 coverage identifies
room for a reranker or a clarification step, but does not show either will work.
Increasing k also spends more of a downstream evidence/query budget.

**Equal field fusion loses useful description ranking.** Names matching generic
words can promote unrelated entities. Treating the name and property rankings
equally underperforms this pooled control. Graph context partly recovers T5
coverage relative to fields but still underperforms pooled search. Neighborhood
text propagation alone is not evidence for a graph-reasoning improvement.

**Source-independent exact lookup surfaces T3 anchors.** Exact candidate recall
is 1.0000, but exact-name/ID ambiguity is
0.3861 of T3 questions. This supports investigating Q59's
lookup ordering while preserving collisions. It does not measure the Q59 fix
through the shipped planner or prove every exact match is the intended subject.

**Incidental exact names are a trap.** T4/T5 exact candidate presence is
0.3942 / 0.4423, while
their exact gold-anchor recall is 0.0000 /
0.0000. A real node name can occur inside a descriptive
question without being the requested anchor. Prepending those hits can displace
the intended candidate. A later ablation should separate explicit subject
mentions from incidental names; do not silently change this run's policy.

**Negative questions still retrieve plausible suggestions.** Every arm produces
candidates on the invented-anchor tier (candidate presence
1.0000); exact candidate presence there is
0.3333. No candidate is automatically accepted.
These are not false-answer rates, but they rule out treating nonempty search as
an answerability signal.

## Threats to validity

- This is an exposed, template-derived diagnostic bank. Description-only
  variants were authored with source descriptions available; lexical coverage
  can overstate performance on independently written analyst questions.
- Gold labels, IDs, source-bank metadata, and gold questions are used only by
  the scorer, never retrieval. An anchor's alternative canonical identities
  count as one gold group. No-anchor cases are excluded with counts shown.
- T1/T2 include intended negative/retired anchors. They remain in the recall
  denominator and have no matching corpus identity; this is **not a positive-
  question accuracy rate**. Missing cases are in `data/metrics.json` under
  `missing_gold_cases`. T3–T5 corpus anchor coverage is complete on this bank.
- Public identifier formatting is not fully declared by current cards. CAPEC's
  canonical IDs differ from user-facing IDs; the scorer translates those forms,
  but the portable retriever does not invent that mapping. T1/T2 therefore do
  not represent a replacement for the existing identifier resolver.
- Every card-declared string property is searchable, including incidental text
  on attached nodes. This increases coverage and competition. Field roles and
  anchor/target roles need independent tests before selective indexing/filtering.
- Graph context is one hop, bounded by neighbor count and text length, sorted
  by canonical ID. Its truncation is recorded per candidate. This is a lexical
  graph-context ablation, not path reasoning or evidence-based reranking.
- The experiment uses local exports. Liveness, access enforcement, live-query
  performance, identity revalidation, and snapshot synchronization require a
  production adapter. The small non-cyber tests establish an interface contract,
  not cross-domain question-answering accuracy.
- No answer precision/recall, records_exact, accepted-entity precision, judged
  correctness, or model cost is measured. No ship threshold was tested.

## What surprised us

The simplest pooled search was stronger on the target tiers than either added
fusion mechanism at the ten-candidate budget. At twenty candidates, graph context
does improve T4 coverage to 0.6699 versus pooled
0.6362; the ranking tradeoff depends on budget,
and this result should not be generalized to all cutoffs. Also, exact occurrence of an existing name is much weaker
evidence of user intent than an identity lookup contract might suggest.

## Follow-ups

Tracked as Q60 in `OPEN_QUESTIONS.md`; see [DESIGN.md](DESIGN.md) for the full
architecture, primary-source references, integration points, and proposed order.

1. Test pooled description retrieval plus evidence-grounded reranking and
   calibrated clarification on a new independently written bank.
2. Test exact-mention roles and card-declared public identifier mappings before
   replacing any existing resolver. Q59 remains open as an end-to-end fix.
3. Bind IDs independently of operation interpretation to address T1/T2.
4. Compare targeted graph exploration with text propagation at matched budgets.
5. Test evidence completeness, compound questions, and transfer to an unrelated
   source with no changes to the generic retrieval core.
