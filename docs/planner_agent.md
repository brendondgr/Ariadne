# Federated Planning Agent

The planning agent (`utils/planner/`) reads the source cards, learns which
graphs are **live right now**, classifies an analyst request, and emits a
**machine-readable plan**: target sources, sub-questions, join keys,
per-sub-question traversal limits, and explicitly unsupported parts. It
*routes*; it never queries. Everything downstream of the plan — specialist
query generation, connector enforcement, synthesis — is out of scope for this
component.

Governing principle: **the model drafts, deterministic code grades.** A drafter
proposes a plan; a fully deterministic self-evaluation gate validates it against
the live-source view and the source cards before it ships.

## Run it

```bash
uv run main.py --plan "Which CAPEC patterns related to credential theft map to ATT&CK techniques, and what mitigations appear for those techniques?"
uv run main.py --plan-llm --plan "<question>"   # use the local OpenAI-compatible LLM drafter
uv run python -m utils.planner.evaluation.run_eval   # score the planner on the expected-plan corpus
```

`--plan` probes the live graphs, prints the live-source view, and emits the
plan as JSON plus a readable summary. Exit code: `0` fully answerable, `1`
partial (some part unsupported), `2` no source cards built.

## Pipeline

```
request ─▶ re-probe live sources ─▶ draft plan ─▶ deterministic gate ─┬─ ok ─▶ emit
                                          ▲                            │
                                          └──── feedback (≤ N) ◀───────┘ reject
                                                                       └─ exhausted ─▶ honest partial plan
```

1. **Discovery / liveness** (`discovery.py`) — a per-request **content probe**
   (connect → non-trivial node count → expected labels present), each bounded
   by its own short timeout in a daemon thread, with a short-TTL re-probe cache.
   Unreachable / unauthorized / empty / timed-out backends are reported
   down-with-reason. This is "read the active graphs in the Docker container."
2. **Drafter** (`drafter.py`, `llm_drafter.py`, `drafter_factory.py`) — behind a
   `PlanDrafter` protocol. The **deterministic** drafter does card-grounded
   keyword routing and builds gate-valid plans by construction; it is the
   default and the always-available fallback. The **OpenAI-compatible** drafter
   posts to a configurable `/v1/chat/completions` endpoint and is used (via
   `HybridDrafter`) when enabled, falling back to deterministic on any failure.
3. **Self-evaluation gate** (`gate.py`) — fully deterministic. Rejects any plan
   that names a non-live source, references a label/edge not in that source's
   card, declares a join that is not the canonical bridge, omits per-sub-question
   limits or exceeds the card's bounds, or is degenerate (silently empty).
4. **ReAct loop** (`agent.py`) — re-probe → draft → gate → feed the specific
   rejection reasons back into the next draft, capped at `max_iterations`. On
   exhaustion it degrades to an honest partial plan (keeps the gate-valid parts,
   names the rest unsupported) — never an infinite loop, fabricated plan, or
   degenerate success. A per-iteration trace is attached for inspectability.

## Source cards and enrichment

Cards are generated by `--build` under `data/source_cards/`. Because the
authored overlays were removed and git-ignored, the generated cards ship with
empty `connection` / `safety` / `provenance` / `entity_descriptions`. The
planner carries that authored metadata in `card_enrichment.py` (committed) and
layers it onto the generated cards at load time:

- **safety** — conservative limits (`max_traversal_depth=3`, `max_result_rows=1000`,
  `query_timeout_ms=5000`, read-only) plus per-backend disallowed clauses/steps;
  CAPEC's generated `allowed_edge_patterns` survive.
- **provenance** — `id_property`, `id_scheme`, `source_name`, `dataset_version`.
- **entity_descriptions** — one-line glosses that improve routing.

The planner reasons only over the **introspected** structural fields
(`node_labels`, `relationship_types`, `allowed_edge_patterns`); glosses are
human context, not routing truth.

## Canonical join keys

Cross-source joins are only proposed on a **declared canonical key present in
both cards** (`join_keys.py`). The single declared bridge is the ATT&CK
technique id: CAPEC `AttackPattern -[MAPS_TO]-> TaxonomyEntry(taxonomy=ATTACK).entry_id`
↔ ATT&CK `Technique`/`SubTechnique.attack_id`. Anything else is marked
unsupported rather than invented.

## Configuration

All via the central `.env` (`utils.config` helpers); real env vars win.

| Variable | Default | Controls |
|----------|---------|----------|
| `NEO4J_URI` / `NEO4J_USER` / `NEO4J_PASSWORD` | `bolt://localhost:5456` / `neo4j` / `password` | ATT&CK probe connection |
| `GREMLIN_URI` | `ws://localhost:6455/gremlin` | CAPEC probe connection |
| `PLANNER_PROBE_TIMEOUT_S` | `4.0` | Per-source liveness probe timeout |
| `PLANNER_CACHE_TTL_S` | `5.0` | Live-source view cache TTL |
| `PLANNER_MIN_LIVE_NODES` | `1` | Min node count for "loaded" |
| `PLANNER_MAX_ITERATIONS` | `3` | ReAct revise cap |
| `PLANNER_LLM_ENABLED` | `false` | Enable the LLM drafter (`--plan-llm` sets it per run) |
| `PLANNER_LLM_BASE_URL` | `http://localhost:9090/v1` | OpenAI-compatible endpoint |
| `PLANNER_LLM_MODEL` | `default-model` | Model name |
| `PLANNER_LLM_MAX_TOKENS` | `4096` | Generation cap (reasoning + plan JSON) |

## Plan schema (emitted)

```json
{
  "request": "...",
  "sub_questions": [
    {"id": "q1", "source": "capec", "text": "...", "entities": ["AttackPattern", "MAPS_TO"],
     "limits": {"max_traversal_depth": 3, "max_result_rows": 1000, "query_timeout_ms": 5000},
     "join_key": "attack-technique-id", "rationale": "..."}
  ],
  "joins": [{"key": "attack-technique-id", "sources": ["capec", "attack"], "on": "..."}],
  "unsupported": [{"description": "...", "reason": "..."}],
  "assumptions": ["..."],
  "rationale": "...",
  "partial": false,
  "trace": [{"iteration": 1, "drafter": "...", "gate_ok": true, "reasons": [], "sub_questions": 1, "unsupported": 0}]
}
```

## Evaluation

`utils/planner/evaluation/` scores the **plan output** (not the eventual
answer): source-selection precision/recall, unnecessary source calls,
expected-entity recall, schema adherence (via the gate), and honesty (correct
`unsupported`/`partial`). The expected-plan corpus
(`evaluation/expected_plans/*.json`) has `dev` and `holdout` splits and includes
out-of-scope and source-down cases. Run with
`uv run python -m utils.planner.evaluation.run_eval [--split dev|holdout] [--json]`.

## Tests

```bash
uv run python -m pytest utils/planner/tests/
```

Covers cards/enrichment/join-keys, content-probe discovery, the plan schema and
deterministic gate, both drafters (incl. a guarded live LLM test), the bounded
loop, the evaluation harness, and the CLI.
